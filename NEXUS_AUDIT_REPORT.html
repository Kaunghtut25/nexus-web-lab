3. Detailed Findings

🔴 Critical (3)

IDLocationDescriptionReproductionFix
C1 /api/settings
/api/services
/api/projects		 No authentication on write endpoints. All admin CRUD APIs (POST/PUT/DELETE) have zero auth checks. Any HTTP client can modify site content. curl -X POST https://nexus-web-lab.vercel.app/api/settings -H 'Content-Type: application/json' -d '{"siteName":"HACKED"}'
→ Returns {"success":true} and the site reflects changes. 		Add verifyToken() middleware to every POST/PUT/DELETE handler. Return 401 for unauthenticated requests. Ref: src/app/api/admin/auth-guard.ts pattern from SPACE Traveller.
C2 /api/auth/route.ts Hardcoded admin token. The auth endpoint returns "nexus-web-lab-admin-token" as a static string — not a JWT, no expiry, no signing. Can be guessed or extracted from client-side code. Login with admin/admin123 via browser → inspect localStorage → nwl_token = "nexus-web-lab-admin-token".
Anyone who knows this string can set it in their browser and access the admin panel. 		Generate a real JWT with HMAC-SHA256, 24h expiry, signed with a server-side secret. Use the existing auth.ts module's hashPassword/verifyPassword with JWT signing.
C3 /api/contact (GET) Contact messages exposed publicly. GET /api/contact returns all submitted messages including names, emails, phone numbers, and message content — without authentication. Visit https://nexus-web-lab.vercel.app/api/contact in a browser or curl.
Returns full JSON with 2+ contact records including PII. 		Move GET /api/contact behind auth. Public should only POST. Admin panel fetches with token in Authorization header.

🟠 Major (5)

IDLocationDescriptionReproductionFix
M1 Root layout Missing robots.txt and sitemap.xml. Neither file exists in public/ or as a Next.js route. Search engines cannot crawl or index the site properly. curl https://nexus-web-lab.vercel.app/robots.txt → 404
curl https://nexus-web-lab.vercel.app/sitemap.xml → 404 		Add public/robots.txt and src/app/sitemap.ts. Reference SPACE Traveller implementation as template.
M2 Root layout Missing OpenGraph and Twitter Card meta tags. Social sharing shows generic preview. No og:image, og:title, twitter:card. Critical for a web agency's own site. Share nexus-web-lab.vercel.app on Facebook/WhatsApp/Twitter → no rich preview. Add openGraph and twitter fields to metadata in layout.tsx. Include a 1200×630 og:image.
M3 src/lib/db.ts Duplicate password hashing in two places. db.ts defines a simple hashPassword() using SHA256 (not scrypt), while auth.ts properly uses scrypt with salt. The auth route uses db.ts's SHA256, bypassing the proper auth module. src/app/api/auth/route.ts imports hashPassword from nowhere (uses inline crypto.createHash). The proper auth.ts module with scrypt is unused by the auth route. Replace the inline hash in auth route with imports from @/lib/auth. Use verifyPassword() from auth.ts consistently.
M4 /api/services, /api/projects (POST) POST with empty body returns 500. POST /api/services -d '{}' crashes because body.title is undefined and INSERT fails. Should validate and return 400. curl -X POST https://nexus-web-lab.vercel.app/api/services -H 'Content-Type: application/json' -d '{}' → 500 Internal Server Error Add request body validation in POST handlers. Return 400 with descriptive error if required fields (title) are missing.
M5 All admin pages Admin auth is client-side only. AuthGuard checks localStorage.getItem("nwl_token") which can be set manually in devtools. Admin pages still render content before the guard redirects (flash). No server-side route protection. Open devtools → localStorage.setItem("nwl_token", "anything") → refresh → admin panel accessible without real credentials. Implement server-side auth check in admin API routes. Even if client-side guard is bypassed, API calls should fail without valid JWT.

7. What's Working Well

  • Design system — Consistent navy+blue+cyan palette, well-structured CSS variables, clean card system. All pages share the same visual language.
  • Dynamic content — All public pages fetch from API with proper loading and empty states. Services and projects pages handle 0 items gracefully.
  • Database schema — Well-designed tables with proper constraints (UNIQUE, PRIMARY KEY, DEFAULT values). Seed data is comprehensive.
  • Image upload — Working file upload with base64 storage in Turso DB. MIME type preservation and caching headers.
  • Responsive layout — Mobile hamburger menu, responsive grid, proper breakpoints. Admin sidebar has mobile slide-over.
  • Contact form — Saves to DB, shows success state, handles errors gracefully.
  • Header/Footer — Dynamic from settings API, scroll-aware sticky header, consistent across all pages.
